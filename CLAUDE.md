# CLAUDE.md

Guidance for Claude Code and other AI coding tools working in this
repository. Human contributors should start with `CONTRIBUTING.md`; the rules
below apply to everyone.

## What this is

Keystrand is a native macOS 26 Redis and Valkey client in Swift 6 and
SwiftUI, designed to look like a first-party Apple app with Liquid Glass.

## Documents

- `docs/DESIGN.md` is the design contract. It wins over the architecture doc
  on anything visual or structural (window model, components, menus, idioms,
  Liquid Glass rules).
- `docs/ARCHITECTURE.md` sections 1-10 are the API contract: target layout,
  constraints, recorded decisions, threading rules, how code gets services
  and sessions, test DB indexes, and known gaps. Section 11 is a public API
  reference generated by `scripts/make-api-reference.sh`; grep it for a
  type, do not read it top to bottom, and rerun the script when a `public`
  symbol changes (CI fails when it is stale). If the doc and the code
  disagree, the code wins.

## Commands

All real code is in the SwiftPM package `KeystrandKit` (`Package.swift`).
`Keystrand.xcodeproj` and `Config/Info.plist` are generated by xcodegen from
`project.yml` and are git-ignored. Edit `project.yml`, never the generated
files. The app target is a synced folder, so new files need no regenerate.

```bash
swift build --scratch-path .build/dev                         # package
swift build --scratch-path .build/dev --target BrowserFeature  # one target

# Tests (live tests need the Redis 8 container on 6390; Valkey tests
# also need 6392 and the 7001-7003 cluster; Sentinel tests need the
# sentinel target)
scripts/test-servers.sh start redis   # or no argument for all containers
swift test --scratch-path .build/dev
swift test --scratch-path .build/dev --filter BrowserFeatureTests

# Debug app
xcodegen generate
xcodebuild -project Keystrand.xcodeproj -scheme Keystrand \
  -destination 'platform=macOS' -derivedDataPath .build/dd build
open .build/dd/Build/Products/Debug/Keystrand.app

# Release build into dist/, signed and installed to /Applications
# Flags: --skip-build, --open. Env: SIGN_IDENTITY, INSTALL_DIR.
scripts/install.sh

# Formatting (needs swiftformat, ast-grep and jq), for the repo or given
# paths. --check changes no files and exits 1 when a change is needed.
scripts/format.sh [--check] [path ...]

# Regenerate bundled data (Python 3 standard library only)
python3 -I scripts/make-redis-commands.py <cache dir>  # redis.json, module files
python3 -I scripts/make-sample-data.py  # Browser, Vector Search samples
scripts/sync-strings.sh          # Keystrand/Localizable.xcstrings
scripts/make-api-reference.sh    # ARCHITECTURE.md section 11
scripts/check-generated.sh       # every generator, fails when one is stale
```

`swift test` compiles every test target into one bundle, so a compile error
in any target blocks all tests. The build has no warnings, and CI builds
with warnings as errors.

### Running the app for checks

Set `KEYSTRAND_DISABLE_AUTODISCOVERY=1` (first-run auto-discovery probes
every local port, including 6379) and `KEYSTRAND_DATA_DIR=<dir>` (keeps the
real store in Application Support untouched).

```bash
KEYSTRAND_DISABLE_AUTODISCOVERY=1 dist/Keystrand.app/Contents/MacOS/Keystrand \
  --open 127.0.0.1:6390/4 --section workbench --tool cli
```

The launch flags (`--home`, `--open-id`, `--key`, `--sheet`, `--inspector`,
`--settings`, `--appearance`, `--window-size`, and others) are listed in
DESIGN.md section 9.1 and parsed in `Sources/AppShell/LaunchOptions.swift`.
`scripts/snapshot.sh <out.png> [flags]` launches the app with a fresh data
directory, captures only its window, and quits it. Set `APP=<path to .app>`
to capture a Debug build instead of `dist/`.

## Architecture

Each layer depends only on the layers above it.

```text
RESP
RedisClient, Formatters, CommandSpecs
RedisCore
RedisUI
Features/* (10 targets)
AppShell
Keystrand app
```

- `RESP`, `Formatters`, and `CommandSpecs` are pure, `Sendable` value code.
- `RedisClient` is the transport: the `RedisConnection` actor (NWConnection,
  TLS, pipelining, Pub/Sub and MONITOR streams), `ClusterClient`,
  `SentinelResolver`, and `SSHTunnel` (spawns `/usr/bin/ssh`).
  `MockRedisClient` is the scripted client for tests.
- `RedisCore` holds models, JSON and Keychain persistence, `DatabaseSession`,
  and the shared services. It `@_exported`-imports the four lower targets.
- `RedisUI` is the component kit from DESIGN.md section 4 and re-exports
  `RedisCore`, so a feature imports only `RedisUI`.
- **Features never import each other.** A type-specific service lives in the
  feature that uses it; `RedisCore` keeps only code two or more targets share.
- `AppShell` composes the features by injecting closures and views (for
  example `KeyDetailsComposer` into `BrowserView(keyDetails:)`).

### Sessions and windows

- One `DatabaseSession` per database id, held by `SessionRegistry`, in a
  `WindowGroup(for: DatabaseID.self)` window. The session closes only when
  its `NSWindow` closes, not on minimize, hide, or tab merge.
- AppShell passes the session to each section view as `init(session:)`.
  Sessions are never in the SwiftUI environment; `AppServices` and
  `SettingsStore` are.
- UI state that must survive section switches lives in
  `session.scopedObject(MyViewModel.self) { ... }`. Conform to
  `SessionScopedObject` to clean up when the window closes or the connection
  resets.
- Commands go through `session.execute`, `session.pipeline`, and
  `session.nodes(role:)`. Pub/Sub, MONITOR, and the CLI use
  `session.makeDedicatedConnection()`. Watch `session.dbGeneration` to reload
  after a logical-DB switch. Navigate with `session.navigator.navigate(...)`.
- Before a destructive write, call `await session.confirm(...)` or
  `context.confirmProduction(_:)`. `CommandExecutor` does not enforce
  confirmation; every caller must.
- Report a failed user action with `session.toasts.error(...)`; AppShell
  shows it as an alert. There are no success or status messages: a visible
  result reports nothing, other results show inline in the sheet, popover, or
  bar that started them.
- Key equivalents live in the `MenuShortcut` table in
  `Sources/AppShell/AppCommands.swift`. `AppShellTests` checks it against
  SettingsFeature's `ShortcutCatalog`, so a shortcut change updates both.
- A section with several pages switches them in place. Do not push a
  `NavigationStack` page; that hides AppShell's toolbar items.

### Concurrency

- Swift 6 language mode, complete concurrency checking, no
  `defaultIsolation`. UI types state `@MainActor` explicitly.
- Connections, `ClusterClient`, `SSHTunnel`, `ClientPool`, and all
  persistence stores are actors. View models are
  `@MainActor @Observable final class`.
- Session-bound services (`KeyScanner`, `KeyOperations`, `CommandExecutor`,
  and others) are `@MainActor struct`s. Move CPU-heavy work into
  `nonisolated` static functions or `Task.detached`.
- Pure static helpers on a main-actor type must be `nonisolated`: Swift
  Testing's `#expect` does not flag a main-actor call from a nonisolated
  test, and the call traps at run time.
- Use `AsyncStream`, not Combine; GCD only where AppKit or Network needs
  it. Guard shared mutable state in non-actor classes with `Mutex`. Every
  `@unchecked Sendable` and `nonisolated(unsafe)` needs a one-line comment
  saying why it is safe.
- An unlabeled trailing closure binds to the first closure parameter. When a
  function has two defaulted closures, label the second one.

## Tests

The tests use Swift Testing. Helpers are in `Tests/TestSupport`.

- The live test server is `127.0.0.1:6390`. **Never touch
  `127.0.0.1:6379`**: a developer's local Redis may be running there.
- **Never send `FLUSHDB` or `FLUSHALL`**, from tests or manual checks.
  RediSearch on Redis 8 drops every index on any flush, even of another
  logical database. Use `RedisTestServer.flush(db:)` or
  `freshConnection(db:)`, which delete with SCAN + UNLINK.
- Each test target owns one logical DB index (ARCHITECTURE.md section 8).
  Seed manual test data on that index only.
- Search and vector tests use DB 0 with a unique key prefix
  (`uniquePrefix(_:)`) and a unique index name, and drop both afterwards.
- Live tests carry the `live` tag and skip, not fail, when the server is
  down or lacks a module they use:
  `@Test(.tags(.live), RedisTestServer.live(.redis, modules: .json))`
  (also `.valkey`, `.valkeyCluster`, `.sentinel`; `RedisTestServer.needs(...)`
  adds a module to one test of a live suite). A test of a command newer than
  Redis 7.2 or Valkey 8 also takes `RedisTestServer.needs(.hashFieldTTL)` or
  `.needs(.array)`, because the nightly runs those older servers.
  `KEYSTRAND_REQUIRE_LIVE=1` turns a missing server into a failure;
  `KEYSTRAND_SKIP_LIVE=1` skips every live test.
- `scripts/test-servers.sh [native] [start|stop|status] [all|redis|valkey|cluster|sentinel]`
  manages `keystrand-test` (Redis 8, 6390), `keystrand-valkey` (Valkey 9
  bundle, 6392), `keystrand-vkc-0/1/2` (Valkey 9 cluster, 7001-7003), and
  `keystrand-sentinel{,-primary,-replica}` (Redis 8 primary 6394 and replica
  6395, Sentinel 26394, group `keystrand-primary`). `native` runs Homebrew
  servers instead of Docker (CI does); native Valkey has no modules.
- Every Sentinel test is in the one serialized `SentinelLiveTests` suite,
  because its failover test swaps the primary and the replica. Find the
  primary through the Sentinel, never by port.
- Use `MockRedisClient` or `RedisTestServer.mockSession(...)` when no server
  is needed, and `RedisTestServer.makeServices()` for a temp-dir
  `AppServices` with in-memory secrets.
- ConnectionsFeature tests inject ports into auto-discovery and never probe
  6379.

## Conventions

- **No third-party packages.** Apple frameworks only.
- Target macOS 26 APIs directly. No `#available` fallbacks.
- Semantic system colors and the user's accent color only: no hex colors,
  palettes, or `Theme` tokens in `Sources`. Editors, the CLI, and the
  Profiler take colors and fonts from `EditorAppearance`.
- No web idioms: no toasts, skeleton loaders, cards, pagination controls, or
  hand-rolled hover states. Build sheets on `SheetForm` with
  `.sheetSize(...)`; use `ContentUnavailableView` for empty and failed states.
- Key names and values are `Data` at the protocol layer. Keys that are not
  valid UTF-8 must still list and open.
- Typed errors (`enum XxxError: Error, LocalizedError`). Never crash on bad
  server input. No force unwraps or `try!` outside tests.
- Format counts with `NumberFormatting.grouped` (locale-independent
  `2,016`). Access bundled resources with `Bundle.module`.
- Use the standard names in UI text and code (Browser, Workbench, Key, TTL,
  Slow Log, Pub/Sub, Profiler, Bulk Actions, Command Helper).
  ARCHITECTURE.md section 2 lists the canonical code names.
- Put a blank line around each multi-line declaration and after each
  multi-line `if`, `for`, `while`, `repeat`, `switch`, or `do` block.
  `scripts/format.sh` adds them.

## ast-grep

`sgconfig.yml` makes the repo root an ast-grep project. Lint rules are in
`ast-grep/rules`, formatting rules in `ast-grep/format`, and their tests and
snapshots in `ast-grep/rule-tests`.

```bash
ast-grep scan                                  # whole repo
ast-grep scan Sources/Features/BrowserFeature  # one path
ast-grep scan --filter no-force-unwrap         # one rule
ast-grep test --include-off                    # rule tests, incl. format
ast-grep test --include-off -U                 # rewrite snapshots
```

Run `scripts/format.sh` and `ast-grep scan` on the paths you changed. Every
lint rule is `severity: error`. A finding means the change breaks a
convention, so fix the code; for a false positive, fix the rule and add the
snippet to its test. Rules: `no-cross-feature-import`, `no-combine`,
`no-observable-object`, `no-try-bang`, `no-force-unwrap`, `no-force-cast`,
`no-custom-color`, `no-availability-check`, `unsafe-sendable-needs-comment`,
`no-xctest`, and `no-flush-in-tests`. Each rule's `message` and `files`
glob say what it checks and where.

The `ast-grep/format` rules are `severity: off` (ast-grep cannot see blank
lines); `scripts/format.sh` runs them after SwiftFormat (`.swiftformat`) and
inserts the missing blank lines around each match.

### Adding a rule

Add a rule only for a convention a syntax shape detects reliably.

1. Write `ast-grep/rules/<id>.yml` with `language: swift`, `severity`, and
   `message`.
2. Write `ast-grep/rule-tests/<id>-test.yml` with `valid` and `invalid`
   snippets. Use a `|` block scalar for a snippet containing `:` or `#`.
3. Run `ast-grep test --include-off -U` and check the new snapshot.
4. Run `ast-grep scan --filter <id>`; each finding must be real.

`files` and `ignores` globs are relative to the repo root; do not start them
with `./`. Add `utilDirs` to `sgconfig.yml` for shared utility rules.

### Swift search notes

- `class`, `struct`, `enum`, `actor`, and `extension` all parse as
  `class_declaration`; `protocol` is `protocol_declaration`.
- A declaration pattern must spell out every attribute, modifier, and
  inheritance clause, so `@Observable final class $NAME { $$$ }` matches
  nothing. Use a `kind: class_declaration` rule that `has` a `modifiers`
  node with an `attribute` matching `^@Observable$`.

- `import $M` does not match attributed imports (`@_exported import RESP`).
  Use `--kind import_declaration`.
- `@unchecked Sendable` parses as an `attribute` child of the declaration;
  `nonisolated(unsafe)` is a `member_modifier` inside `modifiers`.
- `$VALUE!` matches force unwraps but not implicitly unwrapped types.
